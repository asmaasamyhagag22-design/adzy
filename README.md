# ADZY

**Turn a brand website into research, a reviewed strategy and creative work.**

ADZY is a marketing workspace for brand owners and marketers. Give it a business URL and an objective; inspect the sourced profile and competitor research, review the strategy, then carry the approved direction into creative production.

## Inside Adzy

![Actual Adzy creative workspace showing a fictional integration result](docs/images/synthetic-poster.png)

*Actual application UI with fictional Studio Fixture evidence and synthetic provider/vision responses. The rendered poster demonstrates the integrated application flow; it is separate from the historical generated concepts above.*

**Discover → Think → review SWOT → review Strategy → Create → Work**

- **Discover:** enter a URL and inspect the resulting brand profile.
- **Think:** inspect sources, competitor insights, SWOT, positioning and research gaps.
- **Review:** approve or reject the exact displayed strategy. A newer version requires a new decision.
- **Create:** use the approved audience, message, supporting proof and creative boundaries.
- **Work:** revisit saved creative output and its recorded status.

## Run it

The credential-free application demo uses fictional evidence and a disposable local PostgreSQL database. It supports the browser review journey without provider keys or paid generation.

```bash
python3 -m venv .venv-app
source .venv-app/bin/activate
python -m pip install -r requirements-app.txt
python -m pip check
docker pull postgres:16-alpine
python -m workflows.app_demo init --directory .review-app-demo
python -m workflows.app_demo serve --directory .review-app-demo --port 8000
```

Open **http://127.0.0.1:8000/app**, sign in with the fictional credentials printed by `init`, then open **Think → Review strategy**. Stop and restart the same server to test persisted review. Live generation requires separate provider configuration.

## Engineering and verification

The review UI runs a real **LangGraph** workflow with three deterministic typed **LangChain** inspection tools. **PostgreSQL** owns business records and approvals; **SQLite** stores local review progress. Optional **Langfuse** observations are redacted and disabled by default. Paid creative execution remains in the existing pipeline, outside the graph.

- **23 focused tests passed** for the review graph/application boundary, including stale decisions, ownership, concurrent submissions, failed starts and local SDK export behavior.
- **Observed browser journey:** sign in → pause for review → refresh → restart application → resume the same workflow → one approval for the reviewed subject → Creative Direction.
- **Clean-source reproduction:** locked installation, workflow demo and full application startup/authenticated review verified on Python 3.12/Linux.

[Architecture and recovery](docs/architecture/app_review.md) · [Verification scope](docs/validation/app-review-integration.md) · [Publication inventory](docs/publication/manifest.json)

Current scope: one application instance with local checkpoints and existing demo-grade authentication. Hosted Langfuse ingestion, production operation, live-provider quality and campaign performance are unverified. Source references improve inspection; they do not guarantee factual correctness. Complete semantic grounding and paid-operation reservations remain open work.
