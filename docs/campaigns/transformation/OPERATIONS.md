# Campaign operator pilot

This profile supports one trusted operator on a dedicated Linux workstation. The browser, one Uvicorn worker and PostgreSQL 16 run on the same host and use loopback listeners. An administrator provisions accounts. Deployments should use a private OS account and restrict both loopback listeners to the trusted host. A shared shell account, a reverse proxy and public access fall outside this profile. The Campaign planner accepts Arabic and English and attempts bounded capture of public HTML. A publisher can block collection or return evidence that requires human review. The operator reviews sources, copy and both images for each revision before approving. The pilot mounts Campaign only and disables paid dispatch. The model budget is $0.

## Setup and state

From a clean checkout, use Linux x86_64 and Python 3.12. Install `requirements-app.txt`, run `python -m pip check`, and install Chromium with `python -m playwright install --with-deps chromium`. Use a dedicated PostgreSQL data directory or volume. The disposable drill uses the tested immutable image reference `postgres:16-alpine@sha256:721873c34ceb9f8d8fc265984940dc982404c105f19ad51be9fdc5970a6080ea`. Provision a dedicated database and apply standard OS/database permissions. Publish the database only on `127.0.0.1` and set a password. Keep a record of the release SHA, interpreter, lockfile, Playwright, renderer and database image before updating.

Supply `BASEERA_DATABASE_URL` (`postgresql+psycopg` with the URL-encoded password and loopback host) and `BASEERA_AUTH_SECRET` (at least 32 bytes generated by a secure randomness source) through an operator-managed environment. Store these independently of the repository and of the backup. Use an owner-only state directory. The point of explicit signing state is that sessions survive process restarts. To invalidate all sessions, replace the signing secret and restart. Account and brand ownership is transactional in PostgreSQL. A public domain has a single application owner and shared-brand tenancy is unavailable. The browser uses a bearer session in local storage. Individual session revocation and internet-facing TLS are outside the operator setup.

```bash
install -d -m 700 /var/lib/adzy-campaign
python -m alembic upgrade head
python -m workflows.campaign_pilot account \
  --state /var/lib/adzy-campaign --email operator@example.org
python -m workflows.campaign_pilot serve --state /var/lib/adzy-campaign --port 8020
```

Open `http://127.0.0.1:8020/app`. `GET /api/health` reports process liveness. `GET /api/ready` checks the PostgreSQL schema and local writes. Use the catalog and Campaign tab. Other legacy navigation remains visible in the shared frontend. The local server mounts only Campaign, auth login/session, and read-only brand routes. It denies non-loopback Host headers, limits each POST to 32 KiB and five seconds of body transfer, disables access logging, and caps accepted Uvicorn concurrency at sixteen. Login and the existing auth scheme rely on the trusted-host boundary. A launch with `--snapshot docs/demo/campaign-snapshots/buffalo` replays the committed source captures at their frozen clock. Add the portfolio edition path as `ADZY_CAMPAIGN_EDITIONS_FILE` to replay the curated case. Be explicit about live and replay mode when recording outcomes.

## Recovery and upgrade

1. Stop the service to quiesce writes. Create a PostgreSQL custom-format `pg_dump` of the dedicated database. Keep it private and copy it to independently controlled storage. Back up signing configuration separately. Keep the source release with the dump. Preserve the local state directory if in-progress preview cache is valuable. Exact approved ZIPs live in PostgreSQL, including both images and the review receipt.
2. Test a restore into an empty database with `pg_restore --exit-on-error --single-transaction`. Start the matching application and check readiness. Sign in and compare an approved archive SHA-256 with the pre-backup digest. A fresh draft state directory suffices for checking approved downloads. If an approved artifact read fails integrity checks, preserve the failing record for diagnosis and recover the verified backup. A fresh approval is necessary if the original approved artifact cannot be recovered.
3. For an upgrade, keep a pre-upgrade backup and old code. Apply the new migration as a distinct operator step, then start the matching binary. Startup rejects incompatible schema heads. Restoring the previous binary **and** pre-upgrade database is a rollback with data loss since that backup. Keep a separate current backup before rollback. Prefer restoring the current build and data when approvals were finalized after upgrading. Downgrade protections prevent dropping recorded bound approvals. The previous build cannot serve the current schema.

## Monitoring and response

Capture Uvicorn structured events in a private log. Run the monitor each minute under the same OS account using the system scheduler. It scans the most recent five minutes and emits an explicit state if there were no events. Retain rollout and drill logs separately. Alert delivery uses a loopback HTTP receiver with stable idempotency keys. The receiver must deduplicate overlapping reports. Schedule liveness and readiness probes separately because a completely stopped service cannot emit its own telemetry.

```bash
python -m workflows.campaign_monitor /var/log/adzy/campaign.log \
  --local-receiver http://127.0.0.1:9040/alerts
```

| Signal or failure | Response |
| --- | --- |
| `PAGE_TOO_LARGE`, timeout, claims blocked | Inspect the bounded reason and source URL in the application. Supply a smaller relevant public page if one exists, or leave the campaign blocked. Three distinct oversized runs within five minutes trigger an alert. |
| `CAMPAIGN_RESEARCH_BUSY` or `EXPORT_BUSY` | Wait for an in-flight request to finish. Check the current run before retry. There are up to three planning/refresh slots and one render/export slot per worker. There is no durable in-flight queue or cancellation. |
| Lost connection or worker stopped while planning | Read planning state and repeat the same request ID and inputs. Completed matching requests replay the result. Interrupted pre-commit research may have to run again. |
| Stale revision or approval | Reload, review the new revision and preview both images before giving a new approval. |
| Database unavailable or schema mismatch | Keep the service stopped or unready. Confirm the database and expected head, then migrate deliberately or restore the compatible release/database pair. |
| `NO_EVENTS_IN_WINDOW` or receiver error | Check liveness, readiness, log permissions and traffic volume. Non-2xx local receiver responses fail the monitor invocation. Successful operational telemetry says nothing about editorial correctness. |
| Anticipated or uncertain provider charges | This profile has no dispatch route. Investigate the paid path that admitted the attempt. Preserve request receipts and uncertain exposure until it is reconciled with the provider record. |

## Reproduce the candidate check

Use a new output directory. The raw temporary outputs include disposable data and should remain private. The drill uses one snapshot and a separately labelled simulated source failure. It measures twenty sequential plans and twenty warm authoritative ZIP reads, followed by a same-revision eight-client burst. The local targets established before measurement are 20/20 HTTP successes per sequential stage, plan p95 ≤2 seconds, warm export p95 ≤1 second, and one exact archived ZIP recovered from a fresh database. The small workload models a single operator; the burst checks controlled rejection, separate from the latency sample. It does not model live publisher latency, CPU-intensive render concurrency or a public deployment. Browser smoke tests separately include fresh rendering. An older clean checkout is needed to exercise migration compatibility and whole-release rollback.

```bash
docker pull 'postgres:16-alpine@sha256:721873c34ceb9f8d8fc265984940dc982404c105f19ad51be9fdc5970a6080ea'
python tools/drill_campaign_pilot.py --output /tmp/adzy-campaign-drill \
  --previous-checkout /absolute/path/to/clean-133181f-checkout
```

The hosted workflow configuration adds a fresh PostgreSQL/Chromium Campaign journey and targeted concurrency, evidence and transport checks. The local receipt is evidence for this host. The branch protection settings and a hosted run of the candidate require a separate remote action.
